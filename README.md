# Мой ритм

Telegram Mini App с заметками, делами, привычками и личными финансами. Дизайн: тёмный монохром, скульптура, свободные отступы и мягкие переходы. Название рабочее — его можно заменить.

## Что работает

- Сегодня: привычки по расписанию, разовые дела, отметки, будущие дела и краткий итог расходов.
- Заметки: создание, редактирование, удаление, закрепление, поиск, свои разделы. Из заметки можно создать дело или привычку.
- Привычки: выбранные дни недели, дата начала, отметки за текущую неделю, архив и удаление.
- Финансы: доходы и расходы, копейки, свои категории, дата и раздел, месячные итоги. «Разница» — разница доходов и расходов за выбранный месяц, не банковский баланс.
- Общие разделы: создать, переименовать, удалить. При удалении раздела записи остаются в «Без раздела».
- Выгрузка всех записей в JSON. Автоматического восстановления из файла в этой версии нет.
- Бот: `/start`, текст в заметки, `/task`, `/expense`, `/income`, кнопка открытия приложения.
- В Telegram записи привязаны к проверенному Telegram ID. У разных пользователей разные данные.
- В обычном браузере открывается отдельный режим пробы: пример и его изменения хранятся только в localStorage данного браузера. Данные демо не переносятся автоматически в Telegram.

## GitHub → Render → Telegram

Потребуются аккаунты GitHub и Render и бот, созданный в официальном `@BotFather`.

1. В Telegram открой **@BotFather**, отправь `/newbot`, задай имя и username. Сохрани полученный токен. Не вставляй его в файлы репозитория, скриншоты и публичные сообщения.
2. Создай репозиторий на GitHub, например `moy-ritm`. Загрузи **содержимое этой папки в корень репозитория**: `package.json`, `pnpm-lock.yaml`, `render.yaml`, папки `public`, `server`, `scripts`, `tests` и остальные файлы. Не загружай `node_modules`, `.env`, `data`.
3. На Render выбери **New → Blueprint**, подключи репозиторий. Render прочитает `render.yaml` и предложит создать веб-сервис `moy-ritm` и базу `moy-ritm-db`.
4. В поле `BOT_TOKEN` вставь токен из BotFather. Проверь выбранные тарифы. Остальные обязательные настройки уже заданы: адрес базы подключится автоматически, секрет webhook сгенерируется, адрес приложения будет взят из `RENDER_EXTERNAL_URL`.
5. Запусти создание и дождись **Live** у веб-сервиса. При первом запуске приложение само настроит webhook, команды и кнопку меню бота. В логах появится `Бот @... подключён.`
6. Открой своего бота в Telegram, отправь `/start`, нажми **Открыть Мой ритм**. Первое открытие в Telegram будет с пустыми личными данными — добавь свои разделы и записи.
7. По желанию в **BotFather → /mybots → твой бот → Bot Settings → Configure Mini App** укажи URL веб-сервиса Render как Main Mini App, чтобы приложение можно было открывать и из профиля бота. Для работы кнопки из `/start` это необязательно.

После новых коммитов в GitHub Render автоматически обновляет приложение. Данные остаются в PostgreSQL.

### Бесплатный тест и постоянное использование

В `render.yaml` указаны бесплатные тарифы для первого теста. **Бесплатная Render Postgres истекает через 30 дней**. Бесплатный веб-сервис засыпает после 15 минут простоя; первое открытие может занять примерно минуту. Для постоянного использования до истечения срока выбери постоянный тариф базы или подключи внешний PostgreSQL через `DATABASE_URL`. При переходе на другую базу данные надо перенести отдельно: подмена адреса сама их не копирует.

Локальный диск бесплатного сервера Render очищается при перезапусках и обновлениях. Поэтому production-режим требует PostgreSQL и не разрешает сохранять личные данные в локальный SQLite.

Актуальные условия: [Render Free](https://render.com/docs/free), [Blueprint](https://render.com/docs/blueprint-spec).

### Если подключаешь обычный Web Service без Blueprint

Создай PostgreSQL отдельно, скопируй его Internal Database URL. Для сервиса укажи:

| Настройка | Значение |
| --- | --- |
| Runtime | Node |
| Build Command | `npx --yes pnpm@10.30.3 install --frozen-lockfile --prod && node scripts/check.mjs` |
| Start Command | `node server/index.mjs` |
| Health Check Path | `/healthz` |
| `NODE_VERSION` | `24` |
| `NODE_ENV` | `production` |
| `DATABASE_URL` | Internal Database URL базы |
| `BOT_TOKEN` | Токен из BotFather |
| `WEBHOOK_SECRET` | Случайная длинная строка из букв/цифр, `_`, `-` |
| `AUTO_CONFIGURE_BOT` | `1` |

`PUBLIC_URL` можно не задавать на Render: используется `RENDER_EXTERNAL_URL`. Для своего домена укажи `PUBLIC_URL=https://твой-домен`. Если подключаешь внешнюю базу с обязательным TLS, используй URL с `sslmode=verify-full` либо `PGSSL=require`; проверка сертификата не отключается.

Если настройка бота не удалась, проверь значения и перезапусти сервис. Можно также один раз выполнить `npm run bot:setup` в окружении с теми же переменными. Приложение не выводит токен в лог.

## Локальный запуск

Нужен Node.js 24.

```sh
npx --yes pnpm@10.30.3 install --frozen-lockfile
npm start
```

Открой `http://127.0.0.1:3000`. В браузере будет режим пробы, работающий без бота и базы PostgreSQL.

Для проверки настоящего сохранения на сервере скопируй `.env.example` в `.env`, поставь `DEV_AUTH=1`, перезапусти сервер и открой `http://127.0.0.1:3000/?dev=1`. Это отдельный локальный профиль, записи сохраняются в `data/ritm.sqlite`. В production `DEV_AUTH` запрещён; сервер завершится с ошибкой, если его включить.

## Как писать боту

```text
Новая идея для проекта
/task Набросать план запуска
/expense 250,50 Кофе
/income 5000 Подработка
```

Обычный текст сохраняется в заметки. Дела без даты видны на «Сегодня». Финансовые команды получают дату сообщения в UTC: при необходимости её можно изменить в приложении. Все записи из бота попадают в «Без раздела», а раздел и категорию можно выбрать при редактировании.

## Проверки и устройство проекта

```sh
npm run check
npm test
```

Интерфейс — обычные HTML/CSS/JavaScript без обязательной сборки. Сервер — Node.js; единственная внешняя зависимость — драйвер PostgreSQL `pg`. SQLite используется только локально. Схема базы создаётся автоматически.

- `public/` — интерфейс, стили, изображения и логика браузера.
- `server/auth.mjs` — проверка подписи Telegram `initData` и срока сессии.
- `server/store.mjs` — PostgreSQL / локальный SQLite.
- `server/service.mjs` — создание, изменение, удаление, контроль версий записей.
- `server/bot.mjs` — сообщения бота; повторная доставка webhook не дублирует запись.
- `scripts/setup-bot.mjs` — настройка кнопки, команд и webhook.
- `render.yaml` — конфигурация Render.
- `tests/` — подпись Telegram, изоляция пользователей, конкурентные изменения, сохранение, суммы и даты.

Удалённые записи не восстанавливаются через интерфейс. Для постоянного использования настрой резервные копии базы у провайдера; JSON-выгрузка доступна в настройках приложения.

В эту первую версию не входят автоматические напоминания, банковские подключения, голосовой ввод, реклама, донаты и офлайн-синхронизация. Для надёжных напоминаний нужен отдельный планировщик, особенно если веб-сервис засыпает.

Изображения в `public/assets` взяты из предоставленных для этого проекта референсов.

Документация Telegram: [Mini Apps и проверка данных](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app), [Bot API](https://core.telegram.org/bots/api).
